# Routines Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cron + timezone routines that run an agent unattended through the shared headless runner, with concurrency and missed-run policies, budgets/caps and a global pause, run history with live logs, and "Open interactively".

**Architecture:** New `src/automation/` module (cron, Routine types, stores, guards, run queue, scheduler, executor) wired in `src/runtime.ts`. Runs execute through `AgentService` (extended with conversation modes and folder targets) and the existing `TrackedRunner`/`ClaudeRunner`; no second copy of spawn/args/kill logic. Routes in `src/http/routes/routines.ts`; UI in `public/modules/routines.js` following `agents.js`.

**Tech Stack:** TypeScript (strict, CommonJS → `dist/`), Express, node:test, the fake `claude` (`test/fixtures/fake-claude-cli.js`), vanilla JS ES modules, playwright-core.

**Spec:** `docs/superpowers/specs/2026-10-17-routines-design.md` (agents: `docs/superpowers/specs/2026-10-17-agents-design.md`).

## Global Constraints

- Branch `feat/routines-impl` (from `main` with agents merged). The untracked `lib/cron.js` is ported to `src/automation/cron.ts` (Task 1) and then `lib/` is deleted; `.clips/` is left alone.
- Routine: `name` ≤ 64; `prompt` ≤ 20 000 chars; `cron` 5-field + IANA `timezone` (default: machine's); presets hourly, daily 09:00, weekdays 09:00, weekly Mon 09:00; `maxBudgetUsd` default **2**; `timeoutMin` default 20, max 120; `concurrency` `coalesce_if_active` (default) | `skip_if_active` | `always_enqueue`; `catchUp` `skip_missed` (default) | `enqueue_missed_with_cap` (cap **25**, never for schedules firing more often than hourly); `conversation` `agent` (default) | `fork` | `fresh`; `target` `{kind:"agent",agentId}` | `{kind:"folder",cwd}`; permission modes `plan|acceptEdits|dontAsk|bypassPermissions`, default `acceptEdits`; `bypassPermissions` only with an explicit `allowBypass: true` flag from the client.
- Stores: `~/.agenv-routines.enc`, `~/.agenv-runs.enc` (newest **500** runs), `~/.agenv-automation.enc` (settings); per-run log `~/.agenv-runs/<runId>.log`, ≤ 5 MB tail kept (the runner's `logPath`).
- Run statuses: `queued|running|succeeded|failed|timed_out|cancelled|skipped|coalesced`; triggers `schedule|manual|catch_up`.
- Scheduler tick **30 s**, injectable clock; global parallel limit **2**; claim-before-run (advance `nextRunAt` and persist *before* creating the run).
- Prompt is passed to the CLI as argv after `--` (supersedes the spec's "prompt on stdin"; verified with the real CLI). Child environment = the server's.
- New write routes (`/api/routines`, `/api/runs`, `/api/automation`) are added to `WRITE_PATHS` in `src/security/AuthService.ts`; `test/routes.inventory.json` is untouched.
- No test calls the real Claude, uses the real HOME, or kills all `node.exe`. No push/tag/publish without the user's explicit approval.
- Match `src/` style (small classes, constructor-injected deps, `HttpError`, shared `src/core/ids.ts` for ids).

## Review Focus

1. **DST and clock edges** — a 02:30 schedule on the spring-forward day (nonexistent) and fall-back day (ambiguous) fires exactly once per day; a laptop that slept 8 h triggers the catch-up policy once, never a storm (Tasks 1, 6).
2. **Restart and crash windows** — crash between claim and run must not double-fire; runs left `running` by a dead server are marked `failed: interrupted by restart`; `nextRunAt` in the past follows `catchUp` (Task 6).
3. **Dangling references** — agent deleted, folder missing, conversation open in a terminal: the run is `skipped` with a reason, the routine keeps its schedule, nothing crash-loops (Tasks 4, 6).
4. **Hostile/odd input** — invalid cron/timezone/enums/oversized prompt → 400; run id and `tail` param on the log route cannot traverse paths or read the whole file when bounded; `bypassPermissions` never set implicitly (Tasks 2, 7).
5. **Runaway protection** — pause, runs/day, daily cost cap are checked *before* spawn, including for manual runs and catch-up bursts; cancel and timeout kill the whole process tree and free the queue slot (Tasks 5, 6).

### Task 6: Scheduler and runtime wiring

**Files:**

- Test: `test/unit/scheduler.test.js`

**Interfaces:**
- Consumes: everything above; `WsGateway.broadcastEvent("runs-updated")` after any run change.
- Produces: `class RoutineScheduler { constructor(o:{routines; runs; guards; queue; settings; now:()=>number; onChange:()=>void}); tick(): void; start(intervalMs?: number): void; stop(): void; startup(): void }` and `class AutomationService { listRoutines(); createRoutine(input); updateRoutine(id, patch); deleteRoutine(id); runNow(id): Run; listRuns(routineId?, limit?); getRun(id); readLog(id, tail); cancelRun(id); openRun(id): Session; getSettings(); setSettings(patch) }`.
- Behaviour: `tick()` selects enabled routines with `nextRunAt <= now`; for each it first persists `nextRunAt = nextCronTime(cron, tz, now)` (claim), then applies guards, concurrency policy (`coalesce_if_active` → `coalesced`, `skip_if_active` → `skipped`, `always_enqueue` → queue another), then enqueues. `startup()` marks interrupted runs, then for routines with `nextRunAt` in the past applies `catchUp`: `skip_missed` → one `catch_up`-free jump (no run, set next); `enqueue_missed_with_cap` → up to 25 `catch_up` runs for the missed slots (guards still apply per run). New routines get `nextRunAt` computed at creation; enabling a disabled routine recomputes it; disabling clears nothing. `runNow` obeys pause/guards, ignores schedule.
